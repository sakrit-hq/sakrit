from sakrit import Sakrit, SqliteLedger, EffectDecl, ArgClass

01 / HONESTY

Exactly once — or it tells you

Strict exactly-once has one impossible spot: the window between an effect firing and its record landing. Sakrit is built around admitting it — it halts loudly and surfaces the ambiguity for a human. Never a silent duplicate, never a silent drop. Proven by killing our own process at every dangerous boundary.

02 / IDENTITY

A reworded retry is the same intent

Agents reword arguments on every retry — so a payload hash mints duplicates. Sakrit keys an effect by which step of which run it is, so a reworded email is the same email, and a forgotten field can never become a second charge.

03 / TRUST

A library, not a platform

import sakrit opens no network connection and pulls in no framework. Apache-2.0 forever, works offline, no account — you run it, you own the ledger. The guarantee is the whole product.

You declare how strong each tool's guarantee can be — from true exactly-once where the provider cooperates, down to a loud, surfaced flag where it can't. Never guessed.

Why isn't what we already do enough?

The obvious fixes each leave a gap.

✕Our framework checkpoints and resumes.
Checkpointing rewinds the agent, not the world. On resume it re-runs steps that already took effect — the charge already cleared, the email already sent. Sakrit is the half checkpointing doesn't cover.
✕We send idempotency keys to Stripe.
Keys work while they're stable — but an agent rarely words a retry the same way twice, so a hash-derived key changes and the charge fires again. And only some providers accept keys at all. Sakrit derives identity from position, for every tool.
✕We wrap tool calls in retry logic.
A retry after a timeout is the trap: the effect may already have landed. Blind retries double-charge; giving up drops the action. Sakrit records before it acts, so it knows — or halts and asks.

And every effect, every replay, every halt lands on one auditable ledger — sakrit audit shows exactly what fired, what replayed, and what's waiting on a human.

Payments
A retry after a crash bills the card twice.
The key names the intent — one per order, drawn from your domain, never a payload hash. Retry the same order and it dedups; a genuinely new order gets a new key and charges.
money_agent/demo.py
from sakrit import Sakrit, SqliteLedger, EffectDecl, ArgClass

CHARGE = EffectDecl(
    "payment.charge",
    {"customer": ArgClass.IDENTITY,
     "amount_cents": ArgClass.IDENTITY},
)

# key = which intent; identity args = proof it's that intent
sk.guard(CHARGE, charge_card,
    kwargs={"customer": "cus_8815", "amount_cents": 4999},
    key=f"order-{order_id}-charge")

Inventory
Six workers race for the last unit. Stock drops once.
Not money — a plain database write. Each worker opens its own connection to one shared ledger; one acquires a lease and writes, the rest wait and replay the winner's result. A stalled "zombie" that returns late is fenced, so stock decrements once (1 → 0) and can never go negative.
multi_worker/demo.py
# one shared file ledger, coordinated across workers
ledger = SqliteLedger("sakrit.db", multi_worker=True)

def worker():
    sk = Sakrit(own_conn(ledger), secret=SECRET)
    return sk.guard(RESERVE, reserve_unit,
        kwargs={...}, key="order-4471-reserve")

# race all six at once → leases + fencing pick the one writer
run_in_parallel([worker] * 6)

Webhooks
The crash lands in the one window it can't reason about.
A process dies between the webhook firing and its record. Sakrit can't know whether it happened — so it refuses to guess. Every retry keeps halting until a human supplies the missing evidence.
ambiguous/demo.py
try:
    sk.guard(CHARGE, charge_card, kwargs={...}, key=key)
except AmbiguousOutcome:
    # raised on every retry — never a silent duplicate or drop

Email
No framework, no money — the same exactly-once.
Declare which args are identity and which are content. A model reweighs the body on every retry — but a reworded body is the same email, so the retry replays instead of sending twice.
quickstarts/plain_quickstart.py
SEND = EffectDecl("email.send", {
    "to":      ArgClass.IDENTITY,   # diff recipient = diff email
    "subject": ArgClass.IDENTITY,
    "body":    ArgClass.CONTENT,    # reworded body = SAME email
})

sk.guard(SEND, send_email, key="welcome-ops",
    kwargs={"to": "ops@example.com",
            "subject": "Welcome", "body": "Hello!"})
